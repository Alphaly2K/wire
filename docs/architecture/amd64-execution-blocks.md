# AMD64 混合指令块

`x64/cpu/ir/segment.rs` 的 register block 保留原 4–16 条寄存器执行路径及 FLAGS 活跃性处理。checked block 为 4–32 条指令，可组合普通整数、宽度扩展、移位、整数乘法、向量搬运/逻辑和标量 SSE；栈操作、call/return、字符串和未降低指令保持原入口。

每个 block 从单个已验证的代码页降低，branch 必须是末条。取指由调用者验证，整块范围还需通过外部观察点检查。API gateway、过程 callback 返回哨兵、Mono trace 入口与预算仍由 Process64 提供停止边界；合作线程时间片和 UI 轮询预算作为相同 work 上限。跨块及 call/return 衔接实验在间接调用负载上退化，未保留。

每条指令仍独立读取、运算并提交目标、FLAGS 或允许的 MXCSR，复用原 scalar/vector/SSE handler。源访存、写出故障、未掩码浮点异常及 guard 保持原顺序；已成功前缀保留，当前失败指令遵守其原事务规则。源数据宽度根据实际访存决定，包括目标 64 位、源 32 位的浮点转换和 16 字节向量。

纯标量 checked block 的事务仅备份 FLAGS 和 RIP。接纳集合排除 POP 等在最后一个可失败动作前修改寄存器的操作；普通读先完成，再写寄存器，内存写失败时最多需要恢复 FLAGS。目的寄存器为 RSP 也遵守这一顺序。通用单步仍保留完整备份，向量和浮点继续走各自原事务。

含浮点或向量的 mixed block 按本次预算前缀先设置 fallthrough RIP，成功后一次提交 work/retired。数据故障或写入证明失败时，从未完成的指令长度恢复当前 PC，只提交已成功前缀；逐条目标、FLAGS 和 MXCSR 效果仍保留。该路径要求所有接纳 handler 不读取 RIP 或计数、仅末条能分支、失败 handler 尚未分支。普通整数块保留逐条计数。混合循环禁止内联，在 macOS 使用独立代码段，避免扩大标量入口的栈帧和派发布局。接纳新指令时必须重新检查这些条件。

批执行中的写入要求落在一个从未作为代码的页内；代码写入、跨页写或其它不具备证明的操作先退出 block，由普通执行器处理。只读访存不能替换余下代码，继续使用原有完整宽度、权限和 guard 检查，可在实际执行到该指令时跨页或读取代码页。缓存条目的 Arc 在可变访存前独立保留，代码权限、generation、映射或翻译替换继续走原失效路径。

新增对照测试检查每个混合入口/预算、浮点状态、受保护/只读数据、向量和转换宽度、块间调用/返回/栈故障，以及跳转到下一代码页的观察与 guard。完整结果及冻结二进制性能对比见[本轮报告](../reports/executor-optimization-2026-10-21.md)。这些块仍是宿主不可执行的 typed IR 数据。
