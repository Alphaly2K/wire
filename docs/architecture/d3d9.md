# PE32 D3D9 资源借用边界

D3D9 私有拥有 COM 对象、vtable、parent/child/pin/lease 关系、stateblock recording、buffer 和 GPU 状态。`d3d9/access.rs` 将外部依赖分为 HeapResources 与 DeviceResources：24 个分配、释放、绑定和 snapshot 方法只借 GuestHeap 与 process heap ID；设备/factory/reset/present 等调用再借只读 window 集合和 Graphics 输出。普通方法及子模块不再接收 ApiState。

根 dispatch 保留 DLL 准入、返回值和原诊断格式，直接借后端，去掉临时 take。对象/vtable 分配、引用归零与 pin 回收、Rc buffer 最后释放、stateblock live/recording 交换、reset 失败回滚和 Present 的 guest 读取 → Graphics upload → frame 计数顺序保持。资源限额和错误码没有改变。

ABI 继续来自原 Hangover 方法表；内部 COM 方法仍走既有路由，不计新增 DLL export。raster/GPU 源码及 shader parser/executor 的算法保持原主体。

基线 `95b284d`。根 facade、24 个 heap 方法、设备与其它子模块均作源码归一或 rustfmt 后逐字对照。初次编译检查发现机械迁移误改 facade，纠正后再验收；两次日志保留。release D3D9 11、library 4 passed / 2 ignored、显式真实 Metal 对照 2、完整 Win32 255 及 fmt/release lib/bin strict Clippy/build 通过。普通领域借用调整不跑性能或游戏矩阵。证据：`wire-out/refactoring-2026-10-14/r3-d3d9-owners32-{source-checks,verification}.json`。
